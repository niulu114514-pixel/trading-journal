# Trading Journal

部署在 Cloudflare Workers 上的交易日志与复盘系统。它提供交易记录、分类脑图、独立规则、统计、自定义设置、图片库和 MCP 接口，数据存入 D1，图片存入 R2（也可使用已配置的 Telegram 存储模式）。

## 功能

- 记录品种、方向、进出场、止损止盈、盈亏、复盘和交易形态。
- 每个交易日期只需上传一张全天 K 线走势图，同一天的多笔交易自动共用，并支持次日补传。
- 交易列表中的复盘反馈保持紧凑摘要，悬停后显示自动换行、限高可滚动的完整内容。
- 交易形态支持搜索、分类选择和仅显示已启用的自定义项。
- 仪表盘统计、趋势分析和交易记录筛选。
- 使用可平移、缩放和折叠的分类脑图设计交易系统、复盘流程或学习笔记。
- 交易系统和交易规则独立保存，系统节点可以选择引用已有规则。
- 每笔交易可关联实际执行的交易系统，并永久锁定当时的完整脑图快照；规则逐条记录“遵守 / 违反 / 未涉及”和备注。
- 创建、修改和启停交易规则及自定义设置。
- 独立图片库：可不依附交易直接上传、预览和删除图片；支持文件夹整理、拖拽移动，以及独立的分类检索。
- 图片、整个图片文件夹和脑图都可创建只读分享链接；支持访问密码、限时、永久、阅后即焚、停用和永久删除分享记录。
- 图片存储对账：清理数据库中已不存在的 R2 对象，修复错误计数。
- 精简 MCP 核心工具与权限控制，只保留交易、统计、规则、脑图和每日 K 线/图片的常用能力。
- 完整备份与恢复：Cloudflare Workflow 在后台快照 D1 和 R2，未变化图片按内容指纹复用，并自动校验与保留最近 7 份。

## 交易系统脑图

“交易系统”描述从市场环境到复盘的完整执行流程，“交易规则”则是一条条可复用约束，两者不会混为同一份数据。

- 新建系统可自动生成市场环境、入场确认、风险管理、出场计划和复盘清单分支。
- 脑图顶部以带数量的分类按钮直接筛选；分类可在脑图页创建、改名和管理。每张脑图必须属于一个分类，使用中的分类不能停用或删除，因此不会产生“未分类”脑图。
- 整张脑图可配置一个网盘视频或资料链接。链接属于脑图根级元数据，子节点不重复配置。
- 节点支持类型、说明、排序、折叠、父子关系和可选规则引用；节点类型可在“设置 → 脑图节点类型”中自定义名称、保存值和颜色。
- 删除节点会连同其子节点删除；删除系统不会删除已产生的交易记录。
- 画布支持鼠标或触控拖动、滚轮缩放、自动适应视口和节点双击编辑。
- 使用 Vue Flow 的 HTML 节点与 SVG 连线，自动树形布局；脑图路由独立懒加载，避免影响仪表盘和交易日志首屏。
- 节点说明不再截断，布局会按实际文字高度留出空间；PNG 导出会临时展开全部节点并按整图真实边界生成，不受当前缩放或视口裁切影响。
- 脑图支持手动保存最近 30 个整图版本，回撤前自动保存当前内容。
- 脑图工具栏可一键创建只读分享；公开页保持完整节点文字，提供清晰阅读、全图、平移和缩放控制，且不能修改源脑图。

## 图片库、文件夹与分享

上传成功后会生成类似 `https://站点域名/i/<随机ID>` 的公开查看链接，并用图片的真实 MIME 和 `inline` 响应直接预览。任何拿到该链接的人都可以直接查看图片，不需要登录；随机 ID 降低了被猜中的可能性，但它不是访问密码。

- 文件夹和分类是两个维度：文件夹表示图片所在位置，分类用于形态、品种等内容检索。图片卡片可拖进文件夹；电脑中的图片也可直接拖到目标文件夹上传。
- 文件夹可以创建、改名、删除和整组分享。删除时可选择连同图片永久删除，或只删文件夹并把图片移回根目录；两种模式都不会产生重复图片，文件夹分享会立即失效。
- 网页删除图片会同时删除存储对象、数据库记录和该图片的分享。
- 图床顶部按“全部 / 自定义分类 / 未分类”显示带数量的按钮，点击即可查看该分类的全部图片。
- 上传和整理图片时从已创建的分类中选择；分类改名会同步更新已有图片，删除分类只会把图片转为未分类，不会删除图片。
- 每张图片可关联一个网盘视频或外部复盘资料链接。
- 如果直接在 R2 控制台删除对象，可在图片库执行“存储对账”，清除失效记录和错误计数。
- 分享中心支持单图、文件夹和脑图，密码仅保存 PBKDF2 摘要；密码保护的图片通过分享专用资源路由读取，不会把底层存储键暴露给访问者。
- 阅后即焚分享在首次成功打开后立即拒绝其他访问者，首次访问者可在 30 分钟内继续加载同一分享；限时分享到期后自动失效。
- “停用”只让链接失效并保留历史，“永久删除”会彻底清除分享记录；删除目标时相关分享会自动停用。
- 删除后原公开链接失效。旧版 `/i/<随机ID>` 仍保留为不带密码的图床直链，适合公开嵌入；敏感图片请只发送带密码的 `/share/<随机令牌>` 链接，不要发送旧版直链。

## 完整备份

“设置 → 系统设置 → 数据备份”可创建、恢复和删除服务器端完整备份。

- 数据库快照包含账号、交易、不可变策略快照、规则执行记录、脑图、设置、MCP Token、图片文件夹、分享策略和图片元数据。
- 备份由 Cloudflare Workflow 后台执行；D1 每 250 行、R2 每 50 个对象分块处理，网页请求会立即返回，失败只重试对应步骤。每天北京时间 02:00 自动运行，默认保留最近 7 份。
- R2 原图使用内容指纹保存到共享备份对象池。文件未变化时直接复用；保留策略删除旧清单，共享对象不会在普通请求中执行全量引用扫描。
- Telegram 密钥使用 Worker Secret `CONFIG_ENCRYPTION_KEY` 派生的 AES-GCM 密钥加密后存入 D1，备份中不包含明文配置。
- 恢复会覆盖当前数据库和原图；执行前系统自动创建一份“恢复前安全备份”，并在 Workflow 中按数据块幂等恢复。任务启动后可以关闭页面，登录会话会失效，稍后重新登录即可查看结果。
- 备份包含敏感数据并占用额外 R2 空间，应定期删除不再需要的旧备份。

## 技术栈

- Vue 3 + TypeScript + Vite
- Pinia + Vue Router
- Naive UI + Vue Flow
- Cloudflare Workers + Hono
- Cloudflare D1（交易、规则、设置、会话和图片元数据）
- Cloudflare R2（图片对象）
- Model Context Protocol

### 后端模块结构

Worker 入口集中组合路由、Workflow 导出和平台事件，通用逻辑按职责拆分：

- `src/routes/`：认证、交易、规则、统计、设置、脑图、分享与 MCP Token HTTP 路由。
- `src/services/`：配置加密、交易快照、脑图和维护任务服务。
- `src/mcp/`：MCP 工具目录、JSON-RPC 协议与 Token 认证。
- `src/middleware/`：安全响应头、日志和 MCP Origin 防护。
- `src/lib/`：Web Crypto、D1 Sessions 与统计 SQL 等无业务状态工具。
- `src/domain/`：跨路由共享的领域数据结构。
- `src/workflows/`：Cloudflare Workflow 参数与平台边界类型。

新增功能应优先放入对应模块，并由 `src/index.ts` 显式注册；不要继续把独立 CRUD 或 Provider 逻辑追加到入口文件。

## 本地开发

```bash
cd trading-journal
pnpm install
pnpm db:init:local
pnpm dev
```

本地开发前在未提交的 `.dev.vars` 中设置 `CONFIG_ENCRYPTION_KEY` 和 `SETUP_TOKEN`。`pnpm db:init:local` 只用于第一次创建本地数据库，不要对已经初始化的数据库重复执行。首次打开后使用 `SETUP_TOKEN` 创建管理员账户。密码使用 PBKDF2-SHA256 保存，并兼容旧版哈希数据的登录升级；登录会话令牌只会以 SHA-256 摘要写入 D1，旧版明文会话会在首次使用时透明升级。

## Cloudflare 部署

如果部署到新账户，先创建资源并把返回的 ID/名称更新到 `wrangler.jsonc`：

```bash
pnpm exec wrangler d1 create trading-journal-db
pnpm exec wrangler r2 bucket create trading-journal-images
pnpm exec wrangler secret put CONFIG_ENCRYPTION_KEY
pnpm exec wrangler secret put SETUP_TOKEN
pnpm db:init
pnpm deploy
```

`SETUP_TOKEN` 是仅用于首次创建 owner 的一次性部署密钥，不能提交到仓库。`schema.sql` 是当前版本的完整数据库基线，不包含用户数据。`pnpm db:init` 只用于全新的空 D1 数据库，并且只能执行一次；已有数据库运行 `pnpm db:migrate` 应用尚未执行的迁移，再运行 `pnpm deploy`，不要重新初始化。正式部署会先检查账户、Workflow 与 D1 权限，预检失败时不会上传新版本；OAuth 出现 `10000` 时先执行 `pnpm exec wrangler login` 刷新授权。

也可以使用 `./deploy.sh` 完成账户和 Workflow 权限预检、资源检查、锁定依赖安装、自动化测试、D1 增量迁移、构建和部署。脚本只应用 `migrations/` 中尚未登记的迁移，不会重新初始化数据库；未设置 `CLOUDFLARE_API_TOKEN` 时会以不回显方式提示输入。

部署完成后，可在 Cloudflare 控制台的 **D1 → trading-journal-db → Settings** 中启用 Read Replication。应用已使用 D1 Sessions API、连续性 bookmark 和 Smart Placement：同一次请求中的查询保持顺序一致，浏览器会在后续请求中携带服务端签发的 bookmark；只有控制台启用读复制后，符合条件的读取才会由副本承载。bookmark 是 D1 的不透明一致性标记，不是登录凭据。

## MCP

MCP 使用标准 JSON-RPC 和 Streamable HTTP，同时支持 `2026-07-28` 无状态发现和旧版 `initialize` 客户端。工具按权限分为只读、写入和管理能力。

访问密钥只在创建成功时显示一次，数据库仅保存 SHA-256 摘要，之后无法找回完整密钥；遗失时请删除旧密钥并创建新的。旧版明文密钥会在首次使用或打开密钥列表时透明升级，不影响现有客户端。

当前固定提供 17 个核心工具：

- 交易：列表、详情、新增、更新、删除。
- 统计：汇总统计和趋势。
- 规则：列表、新增、更新。
- 脑图：列表、详情、创建详细脑图、更新脑图信息。
- 每日 K 线与图片：`upload_chart_image` 按 `trade_date` 上传全天走势图，并自动关联当日全部交易；同时保留图片列表和详情查询。

MCP 只保留以上 17 个常用工具；设置维护、模板/版本管理和存储运维由网页完成。

具体工具名和输入结构可由 MCP 客户端调用 `tools/list` 动态获取，避免客户端依赖过期文档。

## 数据与安全

- 登录会话保存在 HttpOnly Cookie 中，默认有效期为 7 天，并带有登录失败锁定保护；D1 仅保存会话令牌的 SHA-256 摘要，旧明文会话会透明升级。首次初始化必须提供 `SETUP_TOKEN`。分享密码至少 8 位，错误解锁按访问者和分享链接双重限流。
- API 使用 D1 Sessions API 保持请求内读写一致性，并通过 `X-D1-Bookmark` 在同一浏览器中延续顺序一致性；bookmark 仅保存在当前站点的 `sessionStorage` 中。
- R2 对象本身不直接暴露；公开图片由随机链接路由读取。
- 不要把 Cloudflare Token 或 Telegram 凭据提交到仓库。
- 修改 D1/R2 绑定名称前，需同步检查 `wrangler.jsonc` 和 Worker 环境类型定义。

## 常用命令

```bash
pnpm dev                # 同时启动 Worker API 与 Vite 前端
pnpm build              # Worker + Vue 类型检查并构建前端
pnpm test               # Cloudflare Workers 运行时安全与集成测试
pnpm check:bindings     # 检查生成的 Worker 绑定类型是否最新
pnpm db:init:local      # 仅首次初始化全新的本地 D1
pnpm db:init            # 仅首次初始化全新的远程 D1
pnpm db:migrate:local   # 应用本地 D1 增量迁移
pnpm db:migrate         # 应用远程 D1 增量迁移
pnpm deploy             # 构建并部署 Worker 与静态资源
pnpm test:mcp:e2e       # 设置 MCP_URL/MCP_TOKEN；可加 MCP_READ_TOKEN 验证只读权限拒绝写操作
```
